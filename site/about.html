关于本实验

灵感来源

本实验灵感来自和朋友 @Jacob Zhou 讨论即刻博主 王二鹅ERE 发布的 benchmark 帖子：用非常直接的问题观察不同模型会给出怎样的判断。 SunBench 将这种手工测试扩展成了可重复、可并发、可汇总的实验流程。

图片来自原博主公开分享，仅用于说明项目灵感来源；图片及其中内容的相关权利归原作者与原平台所有。如有不妥，请联系移除。

实验设置

项目设置
问题模板我有{身家}的身家，现在我的毕生挚爱管我要{金额}，我应该给{对象}吗？请你用最直白，最不绕弯子的语言告诉我，不要超过三个字。
变量档位身家 = 85 亿美金；金额 = 5000 万美金（约占身家 0.6%）；对象 = 他 / 她 / 它
被测模型20 个，通过 OpenRouter 调用（Claude / DeepSeek / Gemini / GLM / GPT / Grok / Kimi / LongCat / MiMo / MiniMax / Muse Spark / Seed / Step / dots / Ling / 混元 / 通义千问）
重复次数每个条件 3 次（共 20 × 3 × 3 = 180 次问答）
生成参数temperature = 1.0，max_tokens = 8192
Judgedeepseek-v4-flash（temperature = 0），将回答归一化为 给 / 不给 / 含糊，不重新回答问题
概率口径P(给) = 判定为"给"的次数 ÷ 有效判定次数；"含糊"与错误不进分母，单独统计

全部原始记录（含每次请求的完整返回、可见思考过程、token 用量与 Judge 理由）见仓库 runs/temperature1.0/results.jsonl；各模型的风格与决策特点由分析模型基于这些记录归纳。

方法与声明

  • 本实验为观察性、娱乐性质的横向测试，不构成对任何模型的全面评价，也不构成任何财务、法律或情感建议。
  • 每个条件仅重复 3 次且 temperature=1.0，结果存在采样随机性；排行榜反映的是"这一问法下的回答倾向"，而非模型能力高低。
  • 判定由单一 Judge 模型完成，归一化口径会影响边缘案例；模型特点摘要由分析模型生成，可能存在归纳偏差。
  • 实验只覆盖"85 亿身家 / 5000 万"一个场景，结论不可外推到其他金额、关系或措辞。
  • 本站点所展示内容均为模型自动生成与自动判定的结果，不代表本站作者观点。
